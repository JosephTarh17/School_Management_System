# SMS Full UI Implementation Guide (HTML/Tailwind)

This document provides the structural breakdown and core HTML/Tailwind implementation details for all screens in the School Management System. It is designed to give your development agent the necessary context to reconstruct or modify the UI.

---

## 1. Global Layout Structure
Most administrative pages follow a **Standard Dashboard Shell**:
- **Sidebar (`SideNavBar`):** Fixed left, `w-64`, containing primary navigation.
- **Top Bar (`TopNavBar`):** Fixed top, `h-16`, containing search, notifications, and profile.
- **Main Content Area:** `ml-64 pt-16 p-8`, utilizing a light gray background (`bg-surface`) and constrained by a max-width container for readability.

---

## 2. Page Breakdown & Building Blocks

### 1. Landing Page (`{{DATA:SCREEN:SCREEN_7}}`)
*   **Building Logic:** A long-scroll marketing page using alternating sections.
*   **Key Sections:**
    *   **Hero:** Centered typography, `max-w-4xl`, with primary/secondary action buttons and a floating dashboard preview.
    *   **Features Grid:** A 3-column grid (`grid-cols-1 md:grid-cols-3`) using icon-labeled cards to highlight core modules.
    *   **CTA Section:** A full-width section with a high-contrast background to drive "Join Now" conversions.

### 2. Login & Sign Up (`{{DATA:SCREEN:SCREEN_17}}`, `{{DATA:SCREEN:SCREEN_5}}`)
*   **Building Logic:** Centered authentication cards (`max-w-md`) on a subtle patterned background.
*   **Key Components:**
    *   **Auth Card:** `bg-white`, `rounded-xl`, `shadow-lg`, `p-10`.
    *   **Form Groups:** `InputField` components with integrated icons and validation states (e.g., red borders for errors).

### 3. Administrator Dashboard (`{{DATA:SCREEN:SCREEN_16}}`)
*   **Building Logic:** A grid-based layout for high-level oversight.
*   **Key Sections:**
    *   **Metric Cards:** A 4-column row (`grid-cols-4`) using the `Card.vue` component with icon-labeled stats and trend indicators.
    *   **Activity Feed:** A vertical timeline list with status-specific icons.
    *   **Schedule Preview:** A specialized list component showing chronological events with time-badges.

### 4. Attendance Management (`{{DATA:SCREEN:SCREEN_15}}`)
*   **Building Logic:** Filter-heavy data view focused on rapid entry.
*   **Key Sections:**
    *   **Filter Bar:** A horizontal flex container with search inputs, date pickers, and course dropdowns.
    *   **Attendance Table:** A robust `<table>` with sticky headers, checkbox selection, and `StatusBadge` indicators for every row.

### 5. Course Catalog (`{{DATA:SCREEN:SCREEN_14}}`)
*   **Building Logic:** Visual grid of "Course Cards".
*   **Key Sections:**
    *   **Course Card:** `hover:shadow-md` transition, displaying course code (badge), title (headline), and metadata (flex-row for credits/term).

### 6. Class Sessions (`{{DATA:SCREEN:SCREEN_13}}`)
*   **Building Logic:** Time-management focus using a split-view.
*   **Key Sections:**
    *   **Daily Timetable:** A list-view emphasizing time slots and room assignments.
    *   **Session Highlights:** Side-rail cards for "Active" vs "Upcoming" sessions.

### 7. Assessments (`{{DATA:SCREEN:SCREEN_12}}`)
*   **Building Logic:** Gradebook management interface.
*   **Key Sections:**
    *   **Assessment List:** A detailed table showing weights, due dates, and grading status (e.g., "45 submissions pending").
    *   **Action Header:** Global "Create Assessment" primary button.

### 8. Participation Log (`{{DATA:SCREEN:SCREEN_11}}`)
*   **Building Logic:** Qualitative data entry and tracking.
*   **Key Sections:**
    *   **Engagement Metrics:** Summary cards showing "Highly Active" vs "Needs Attention" counts.
    *   **Log Table:** Rows containing text-heavy "Notes" fields alongside rating badges.

### 9. Financial Records (`{{DATA:SCREEN:SCREEN_10}}`)
*   **Building Logic:** Transactional ledger with high-priority alerts.
*   **Key Sections:**
    *   **Financial Overview:** Large-scale currency displays for "Total Collected" and a red-themed "Overdue" alert card.
    *   **Transaction Table:** Color-coded status labels (Paid = Green, Overdue = Red, Pending = Yellow).

### 10. User Profile (`{{DATA:SCREEN:SCREEN_8}}`)
*   **Building Logic:** Settings-heavy layout using a two-column grid.
*   **Key Sections:**
    *   **Identity Card:** Left-side avatar and high-level role/department info.
    *   **Settings Forms:** Right-side tabbed or stacked sections for Personal Info, Security (2FA), and Activity Logs.

## 3. CSS Strategy (Tailwind)
The entire system uses a **Semantic Token approach**:
- **Backgrounds:** `bg-surface` (#f8f9ff) for the app body; `bg-white` for cards.
- **Borders:** `border-gray-200` for standard separation; `border-primary-600` for active states.
- **Typography:** `text-gray-900` for headings; `text-gray-600` for secondary body text.
- **Interactions:** `hover:bg-gray-50`, `active:scale-95`, and `transition-all` on all interactive buttons and cards.
